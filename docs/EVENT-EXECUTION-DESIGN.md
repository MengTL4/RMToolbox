# 公共事件整合与分步执行设计访谈

状态：Q1–Q10 已确认；实现、自动回归、NW 桌面检查与本地 Release 打包已完成（2026-09-07）。

## 用户提出的调整

- 将事件解释器集成到公共事件：选中公共事件后，既能运行整个事件，也能打开解释器。
- 希望按步骤查看，并能运行其中某一步；现已确认为任选完整步骤执行。
- 这是在上一轮只读阅读器基础上新增执行能力；不能直接沿用上一轮“不提供执行控制”的范围定义。

## 访谈开始时的现状

- `app/gui/src/views/DataEventsView.vue` 的详情区只有运行整个公共事件的入口，通过 `commonEvent.run` 请求运行。
- `app/gui/src/views/DataInterpreterView.vue` 是独立只读页，具备指令列表、分页、搜索、原始参数、快照与执行位置显示，没有单步执行操作。
- 词汇表已扩展“事件解释器”的含义，并增加“选步执行”，仍将工具入口与游戏内部执行指令的对象区分。

## 第一轮已确认

1. 采用“选步执行”：任选一个完整步骤执行，不做从头依次推进的顺序单步。
2. 公共事件详情保留运行整个事件的入口，并展开解释器；移除独立解释器页，地图事件共用面板。

补充核实：现有 `commonEvent.run` 仅在 MV/MZ 桥接中有实现，RGSS 分发尚无该命令。公共事件 UI 的同名按钮不能证明三代 RGSS 已具备运行能力；本轮涉及执行时必须补齐或明确能力限制。

## 第二轮已确认

3. 对话连同续行算一步；选项、条件分支与循环按完整结构执行；调用公共事件时运行被调用的整个事件。首版不单独运行结构内部某一行。
4. 公共事件支持选步执行，地图事件共用面板但保留只读。
5. 仅在地图空闲、无对话/战斗/转场时接受执行，一次运行一个步骤，完成后才能再执行，不接管原有剧情。

## 第三轮已确认

6. 缺少地图事件调用上下文的步骤禁止执行，并解释原因，不自动指定调用者。
7. 关闭面板、切换当前游戏不取消执行：步骤在原游戏继续运行，工具箱保留状态，切回后仍可查看。
8. 脚本连同续行作为一个步骤，脚本及插件命令展示原文并确认后允许执行；其行为不能静态保证局限于显示内容。无法识别的非脚本指令标为不支持。

## 第四轮已确认

9. 提供“停止后续指令”：等待已启动操作结束，不启动后续指令，不回滚已产生的效果；同步脚本卡住游戏线程时不承诺立即中断。等待期间明确显示状态，不提前标成已停止。

## 技术核实补充

- MV/MZ 的 `reserveCommonEvent` 表示预约运行，不能将返回成功展示为已经完成。
- 步骤执行需要区分已接受、运行中、等待及结束；对话、移动、战斗、传送和子事件不一定在一次更新中结束。
- 文本/脚本续行、分支结果、循环和标签跳转依赖完整结构；不能用逐行截取替代步骤建模。
- “本事件”目标和独立开关依赖地图事件调用上下文，公共事件列表自身不提供这样的调用者。
- 执行应从游戏端原始事件定义取指令并校验版本，不能把有深度/长度上限的只读展示快照当成可执行原文。

## 实施规格与验收

### 界面

- 公共事件详情保留“运行整个事件”，增加“事件解释器”展开入口；选中步骤后明确点击“执行这一步”，选择步骤本身不执行。
- 移除数据区独立解释器子页；地图事件通过共用面板保留各页、条件、指令及执行位置阅读能力，但没有执行按钮。
- 保留搜索、原始参数、未知指令显示及快照过期提示。结构内部的行继续可读，但不提供独立执行按钮。

### 执行边界

- 步骤来自游戏端原始定义；校验当前游戏、地图身份、事件版本与步骤完整性，旧快照不能提交执行。
- 对话和续行、脚本和续行、移动路线及续行保持完整；选项、分支、循环完整执行，公共事件调用包含其整个调用过程。
- 跳到步骤范围外的事件指令拒绝执行，不自动扩展范围。静态可识别的调用上下文依赖缺失、结构损坏及不支持的命令明确说明原因。
- 脚本和插件动态行为无法全面静态分析，依照 Q8 展示原文并确认，不承诺其不影响其他事件或数据。
- 仅在地图空闲时接受操作；同一游戏一次只允许一个工具发起的事件执行，公共事件整段运行与选步执行不能相互叠加。

### 生命周期

- 区分已接受、运行中、等待、等待停止、已完成、已停止及失败。预约成功不能直接显示完成。
- 游戏端负责已接受步骤的执行；关闭面板或切换当前游戏不会自动停止或转移执行，状态按游戏归属。
- 断线时停止提交操作，将无法核实的执行状态明确标出；重连后查询状态，不自动重放执行请求，也不声称已回滚。
- 停止只针对该次工具发起的执行，不接管其他剧情；已启动操作完成前保持等待，已产生的效果不回滚。

### 引擎与验证

- 延续现有目标引擎范围：MV/MZ、XP/VX/VX Ace；补齐 RGSS 公共事件整段运行与选步执行适配。能力无法识别时说明原因，不伪装成功。
- 测试分组边界、文本/脚本续行、分支/循环、子事件、越界跳转、调用上下文缺失、版本过期、重复执行、等待、停止、切换游戏和断线。
- 复用既有界面回归与真实 NW 冒烟流程，完成后生成本地 Release 包并校验；不自动推送或发布远程 Release。

### 实施顺序

1. 步骤识别、执行校验与游戏端运行状态。
2. 多引擎执行适配、等待及停止语义。
3. 共用解释器面板与公共事件详情整合，移除独立子页。
4. 回归、桌面检查与本地 Release 打包。

Q10 已确认：上述规格与用户理解一致，开始实施。

## 实现记录

- 公共事件详情与地图弹窗共用阅读器，独立子页已移除；地图面板不提供执行或停止控件。
- MV/MZ 与三代 RGSS 通过空闲地图的原生解释器运行捕获的完整步骤及静态公共事件依赖。工具按游戏记录状态，原生等待过程继续由游戏更新。
- 执行前校验完整原始定义版本、地图身份、步骤结构和调用上下文；静态递归公共事件调用拒绝，预检最多 20,000 条指令，脚本确认预览最多 128K 字符，超过限制明确拒绝。
- `events.steps/preview/execute/execution/stop` 提供步骤、原文确认、执行及状态控制。`commonEvent.run` 也须传入地图身份和版本，不能再用裸事件编号绕过整段执行校验。
- 停止在指令边界生效，等待已发起的对话、战斗与移动完成；即使移动路线未勾选等待，也保留运行状态直到移动结束。脚本及插件的动态行为仍适用 Q8 的限制。
- MV 测试使用固定版本的官方 `Game_Interpreter.js`（提交 `182e31449707ba7e406db0485c44c2a9d11e2dcd`，随 fixture 保留 MIT 许可）；MZ 参数分发与 XP/VX/VX Ace 更新、子解释器及 Fiber 行为使用适配 fixture。该验证不等同于所有真实游戏和插件组合实测。
